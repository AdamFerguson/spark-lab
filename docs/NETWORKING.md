# Networking

Two ways to reach the gateway: **Tailscale** for your own devices, and an
optional **Cloudflare Tunnel** for public access. Both are opt-in via
`network` in `config.yaml`.

## Tailscale (private)

Recommended default. Join every device (and the Spark) to one tailnet, then the
gateway is reachable at the Spark's Tailscale IP or MagicDNS name from any of
your machines — no open ports, encrypted by default.

On the node:
```bash
sudo tailscale up          # first time; log in via the printed URL
tailscale status           # see your node + IP / name
```

`spark-lab apply` ensures `tailscaled` is enabled and running. Clients then use:
```
http://<spark-tailscale-name>.ts.net:4000/v1
```
with your `LITELLM_MASTER_KEY`.

Access control is the LiteLLM key: anyone who can reach the port still needs a
valid key. Keep `LITELLM_MASTER_KEY` long and random (generated by `init`).

## Cloudflare Tunnel (optional public access)

Enable `network.cloudflare.enabled: true` and put a tunnel token in
`CF_TUNNEL_TOKEN` (create a **remote-managed** tunnel in the Cloudflare Zero
Trust dashboard; the token is the only secret that goes on the node).

The tunnel is run by the system `cloudflared` service. Spark-lab ensures it's
enabled+running when you `apply`. Configure the tunnel's public hostname and
which local service it fronts (the gateway, `http://localhost:4000`) in the
Cloudflare dashboard.

> Only expose what you're comfortable sharing publicly. Every request still
> needs a valid LiteLLM key — consider issuing per-person virtual keys in the
> LiteLLM UI to separate and revoke access.

## Ports recap

| Service | Port | Exposure |
|---|---|---|
| SGLang | 30000 | host only (reached via `host.docker.internal` inside Docker) |
| LiteLLM gateway | 4000 | your real entry point (Tailscale / Cloudflare) |
| Grafana | 3000 | monitor via Tailscale |
| Prometheus | 9090 | monitor via Tailscale |

Keep 3000/9090/30000 out of any public tunnel — only front the gateway (4000).
